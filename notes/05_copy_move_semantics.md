## 一、先弄清：这一课到底在学什么

你有一个 IMU 数据包 a，里面放着传感器名称和一组测量值。现在程序需要把这组数据交给另一个数据包 b。

最常见的两种需求是：

- **还要保留 a 的数据，另做一份供 b 使用。** 这叫拷贝。比如保留原始 IMU 数据，再对副本做处理。
- **准备把数据交给 b 管理。** 这时可以使用移动。比如把已经整理好的数据包交给下一步处理。

无论拷贝还是移动，还要再问一句：**接收数据的对象是刚创建的，还是已经存在的？**

这一问就把本课的四种操作分清楚了：

- 刚创建接收对象：构造。
- 接收对象已经存在：赋值。
- 再结合“拷贝”或“移动”，得到拷贝构造、拷贝赋值、移动构造、移动赋值。

先学会用代码区分这四种情况。标题中的 Rule of Zero/Five、返回值消除和容器扩容，
都是后面用来解释实际工程现象的内容，读到相应任务时再看。

本课与前三课的连接：用第 03 课的构造/析构描述“对象怎么产生和结束”，
用第 04 课的所有权描述“对象里的数据由谁管理”，再观察复制和交接时发生什么。

## 四、概念笔记：先看具体语句，再看规则

### 1. 判断构造还是赋值

你已经写下的解释保留在表里：

| 语句（a 已存在） | 操作 | 我的解释 |
|---|---|---|
| `MeasurementPacket b = a;` | 拷贝构造 | 利用已有的对象初始化新对象 |
| `b = a;` | 拷贝赋值 | 把已有对象的值赋给另一个已有对象 |
| `MeasurementPacket c(std::move(a));` | 移动构造 | c 在这一行创建；以 a 为来源初始化 c，允许转移 a 的成员资源 |
| `b = std::move(c);` | 移动赋值 | b 已经存在；处理 b 原有资源，再接收 c 的成员资源 |

读第一行时，先看 `MeasurementPacket b`：它在定义一个新对象。
第二行只有 `b = a`：b 早就存在，现在给它赋值。有没有等号不是判断标准。

`other` 是函数参数名，用来代表“数据从哪个对象来”；
`this` 指向“当前正在接收数据的对象”。

**为什么赋值运算符通常返回 `MeasurementPacket&`？**

为了与内置赋值的习惯一致，支持 `a = b = c`，并避免返回值时复制对象。
`this` 指向接收赋值的对象，`*this` 是这个对象本身；`return *this` 返回它的引用。
例如 `b = c` 返回 b 的引用，随后 `a = b`。返回引用不会创建新包，也不会延长对象生命周期。

### 2. 拷贝：先验证“副本改了，原件不变”

在本课里，a 和 b 都有自己的 `vector<double>`。
你已经用“改变 b 的首值，再检查 a”做了这个验证。

先记住这一项实验结论，再联系浅拷贝与深拷贝：

- 本课 vector 的拷贝会复制元素，副本的数据独立。
- 如果成员是裸指针，默认拷贝一般只复制地址，两个对象可能指向同一块内存。
- 如果两个对象还都要释放那块内存，就可能重复释放。

这是不同成员类型的行为区别，不能把 vector 的结果套到所有类上。

我的理解：拷贝是否产生独立资源，取决于成员的拷贝语义。这里 `vector<double>` 复制各个 double，
所以 a、b 有各自的数据存储；`const T&` 只是接收参数的方式，不是“深拷贝”的实现。

我的复制独立性实验：`MeasurementPacket b(a)` 后执行 `b.setFirst(2.0)`，
断言 b 首值为 2.0、a 首值仍为 0.1 均通过。`a = a` 后数量仍为 3、首值仍为 0.1。

### 3. 移动：先看谁接收数据，源对象后来怎样

用这两行做对照：

```cpp
MeasurementPacket b(std::move(a));  // b 这时才创建：移动构造
c = std::move(b);                  // c 必须已经存在：移动赋值
```

两行都表达“可以从源对象移动”，区别在于接收对象是否已经存在。

`std::move` 本身不搬数据。它把表达式变成可供移动操作选择的形式；
真正如何处理数据，要看被调用的构造函数或赋值函数。
你在移动构造中写的 `std::move(other.values_)` 才把成员的移动操作接了起来。

移动后，源对象还存在。不要无条件读取它的第一个元素；
先看是否为空，或者重新给它赋值后再使用。

我的理解：移动提供从源对象转交资源的机会；移动函数负责具体转交，源对象的生命周期没有结束。

本次运行中，a 移给 b、b 移给 c 后，原测量数组的 data 地址沿 a → b → c 保持一致，
各包对象的 this 地址不同。a、b 移后 size 为 0；这是本次输出，不能推广成所有类型的移动保证。
重新赋值后 a 为 `New_IMU / size=2 / first=1`，b 为 `New_GNSS / size=4 / first=2`。
`c = std::move(c)` 因当前实现有自移动判断而保留原值。

<details>
<summary>补充规则：当前两行看懂以后再读</summary>

- `other` 即使声明为 `T&&`，用名字访问它时，表达式仍是左值。
  所以移动其 string/vector 成员时，还要针对成员写 `std::move`。
- 没有合适的移动函数时，`std::move` 可能最终导致拷贝，或在特定重载情况下编译失败。
- 第 04 课中，把 unique_ptr 移给另一个所有者后，源为空有库保证；
  一般的 string/vector 移后状态不能一概当作“必为空”。
- 标准库对象移动后通常有效但状态未指定。仍可析构、查询允许查询的状态或重新赋值；
  读取首元素仍要求非空。自定义类需要保持自己约定的有效状态。

</details>

### 4. Rule of Zero/Five：最后才回答“哪些函数需要自己写”

四种操作与析构一起考虑，重点是维护资源所有权和类的不变量。

五个相关操作是：析构、拷贝构造、拷贝赋值、移动构造、移动赋值。
普通构造函数不在这“五个”里。

- **Rule of Zero：** 成员已经会管理资源时，通常让编译器生成这些操作。
  本课的 string/vector 就能自动管理自己的内存；含 unique_ptr 的类默认可能不可拷贝。
- **Rule of Five：** 如果某个操作需要你专门处理，就把另外几个的行为一起考虑。
  可以自己实现，也可以明确使用 `=default` 或 `=delete`。
- 你手写这些函数，是为了看见调用过程。工程里的普通数据包通常可以写得更简单。
- 只添加一个日志析构函数也会影响隐式移动的生成，所以本实验显式补上移动操作。

收尾用 `PlainMeasurementPacket` 对照验证。
参考：[C++ Core Guidelines C.20/C.21](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#S-ctor)。

我的选择理由：`PlainMeasurementPacket` 只有 string/vector 成员，它们已正确实现资源管理、拷贝和移动，
因此采用 Rule of Zero。教学版手写五个函数是为了观察调用日志。
如果类直接拥有文件句柄，则析构要 close，通常禁止复制，并实现转移句柄、清空来源的移动操作；
也可以先把句柄封装成 RAII 成员，让上层业务类继续采用 Rule of Zero。

### 实验 2：拷贝构造与拷贝赋值（已完成）

`MeasurementPacket b(a)` 用初始化列表复制成员，创建新 b。
`c = a` 对已存在的 c 执行成员赋值；c 的身份和生命周期持续，成员资源由 string/vector 处理。
析构函数只打印，随后成员自动析构，无需手写 delete。

**为什么 b 改了，a 不变？** 两个 `vector<double>` 有独立存储，修改副本不影响原件。
**为什么 c = a 没有新建 c？** 赋值运算符在已有 c 上执行，`this` 仍指向原来的 c。
本课成员支持安全的自拷贝赋值，所以即使没有手写 `this == &other`，`a = a` 也正确。

### 实验 3：移动构造与移动赋值（已完成）

```cpp
MeasurementPacket b(std::move(a));  // 新建 b，移动初始化成员
c = std::move(b);                  // c 已存在，移动赋值成员
```

移动构造用成员初始化列表；移动赋值先判断自移动，再分别给 string/vector 成员移动赋值，
最后 `return *this`。c 原有资源由成员赋值操作负责处理，无需先手工析构 c。

本次已验证：移动后来源仍存在，a、b 可以重新赋值；自移动后 c 的数值保持不变。
这个“自移动保留原值”来自当前代码的早返回，不是所有类型的统一保证。

**noexcept 是什么？** 表示异常不能逃出该函数；若异常逃出，会调用 `std::terminate`，不是忽略异常。
本课默认分配器的 string/vector 相应移动操作支持不抛异常；函数体的日志也必须纳入考虑。
如果为输出流启用抛异常配置，不能再认为日志绝不会影响这一承诺。

**为什么 const 对象经过 std::move 通常仍然拷贝？** `const T` 经转换得到 `const T&&`，
不能绑定到本课的 `T&&`；但可以绑定到 `const T&`，因此本课会选择拷贝。

### 实验 4：按值返回与拷贝消除（已完成）

```cpp
MeasurementPacket makeDirectPacket() {
    return MeasurementPacket("IMU", 3, 0.1);
}
MeasurementPacket makeNamedPacket() {
    MeasurementPacket packet("IMU", 3, 0.1);
    return packet;
}
```

- 直接返回同类型纯右值：本例 C++17 保证直接构造结果对象，不要求经过拷贝/移动构造。
- 返回具名局部对象：可执行 NRVO，但不保证。未执行时，本课可使用移动构造。
- `return packet;` 已经允许 NRVO，并在符合规则时尝试隐式移动；无需写 `return std::move(packet);`，后者会妨碍这里的 NRVO。
- 按值返回安全；返回局部对象的引用会在离开函数后悬空。

**本次输出如何说明按值返回不一定复制？** 正常构建的两个函数都只有一次普通构造，没有 copy/move 日志；
禁用可选消除后，直接返回仍没有移动，具名返回出现一次移动。具体日志见第六节。

参考：[C++17 构造与拷贝消除](https://learn.microsoft.com/en-us/cpp/cpp/constructors-cpp?view=msvc-170)、
[NRVO 规则](https://eel.is/c++draft/class.copy.elision)。

### 实验 5：vector 扩容与插入方式（已完成）

`size()` 是已有元素数量，`capacity()` 是不重新分配存储时能容纳的元素数量。
`reserve(n)` 预留容量，不增加 size；`resize(n)` 改变元素数量，必要时创建或销毁元素。

本次 `reserve(2)` 后实际 capacity 为 2；填满后再插入 GNSS，size 从 2 变 3，capacity 从 2 变 4。
观察到一次新包普通构造、两次旧包移动构造，以及旧位置对象析构。
新存储中的旧元素通过构造建立，不能把这个过程当成给原位置赋值。
容量翻倍和日志先后顺序不是跨实现保证。

| 写法 | 本课在容量足够时的行为 | 对来源的影响 |
|---|---|---|
| `push_back(a)` | 拷贝构造一个容器元素 | a 保留原数据 |
| `push_back(std::move(a))` | 移动构造一个容器元素 | a 进入移后状态 |
| `emplace_back("ODO", 3, 0.3)` | 直接用参数构造元素 | 无外部包对象需要移动 |

`emplace_back` 不保证完全没有移动：若触发扩容，旧元素仍需迁移；
`emplace_back(a)` 也仍会拷贝 a。

**为什么 noexcept 影响扩容？** 对可以拷贝的类型，若移动构造可能抛异常，容器通常拷贝旧元素，
以便失败时保留原内容；若移动构造不抛异常，便可安全地移动旧元素。
如果类型不能拷贝，容器也可能必须使用会抛异常的移动构造，异常保证会受限制。
这里关注的是移动构造的 noexcept，不是移动赋值的 noexcept。

**扩容后什么失效？** 指向 vector 原有元素的指针、引用和迭代器（包括旧 end）全部失效。
包内部的 data 地址即使因移动而保留，也不代表包对象本身的地址仍有效。

参考：[vector 容量规则](https://eel.is/c++draft/vector.capacity)、
[Core Guidelines C.66](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#Rc-move-noexcept)。

### 实验 6：Rule of Zero/Five（已完成）

`PlainMeasurementPacket` 只保留普通构造和业务接口，不声明五个特殊成员函数。
编译器逐成员执行拷贝/移动，string/vector 完成资源管理。

已验证：b 拷贝 a 后修改 b 不影响 a；e 拷贝赋值后修改 e 不影响 a；
移动构造和移动赋值后的目标值正确；移动后的 d 重新赋值为 `REUSED / size=1 / first=4`，断言通过。

**为什么工程中不必手写五个函数？** 成员已经具有所需语义，编译器组合这些成员操作即可。
默认操作不是无条件安全：若成员是拥有资源的裸指针，默认逐成员拷贝只复制地址；
若含 unique_ptr，默认拷贝通常会被删除，表示类不可复制。

| 5 扩容 | 容量用满后插入会迁移旧元素 | size 2→3，capacity 2→4；新包构造一次、旧包移动两次 | 新增一个元素可能触发多个对象构造 |
| 6 Zero/Five | 默认操作组合成员语义 | `Rule of Zero checks passed`，独立副本、移动与复用断言通过 | 标准库成员可承担资源管理 |

## 十、本课总结

1. **最容易混淆的两种操作及区分办法：** 构造与赋值。先判断接收对象是否在该行创建，再看来源是否允许移动；是否出现等号不能作为判断标准。
2. **哪条真实输出帮助理解 std::move：** b 移动构造后的 data 与 a 移动前一致，但 a 的 this 仍存在；说明转移的是成员资源，源对象没有被销毁。真正执行转移的是移动构造函数及成员移动操作。
3. **返回局部对象为什么通常不写 return std::move(local)：** `return local` 已可执行 NRVO，未消除时本课可隐式移动；添加 std::move 会妨碍这里的 NRVO，可能平白增加一次移动。
4. **传感器流水线中按值返回、复制和转移的意义：** 按值返回让函数交付完整的数据包；拷贝适合保留原始测量、独立处理副本；移动适合当前阶段不再需要原数据时交给下一阶段，减少不必要的元素复制。
5. **为什么日志不能证明性能提升：** 日志只能帮助观察调用，输出本身还会产生开销；性能取决于数据规模、分配、优化与使用方式，要靠合适的基准测量，不能只数 move 行。
6. **下一课容器学习继续关注：** reserve 与 resize 的区别；增长何时发生；插入、删除、扩容对迭代器/引用的影响；如何根据访问和修改方式选择容器。

## 十一、八股问答速查

以下按本课 C++17、普通数据类的范围回答。

### 1. 四个特殊成员函数的典型签名是什么？

```cpp
T(const T& other);             // 拷贝构造
T& operator=(const T& other);  // 拷贝赋值
T(T&& other) noexcept;         // 移动构造
T& operator=(T&& other) noexcept; // 移动赋值
~T();                         // 析构
```

`noexcept` 是在实现确实满足不抛异常时给出的承诺，不是移动函数成立的必要条件。
构造函数没有返回类型；赋值函数通常返回当前对象的引用。
默认构造函数也是特殊成员函数，但不属于 Rule of Five 所说的五个。

### 2. 为什么拷贝构造通常接收 const T&，不能接收 T？

引用直接绑定来源，避免为了传参再复制一次；const 允许接收常量对象，并限制通过参数修改来源。
如果按值接收 T，为了构造参数本身就需要再次拷贝，形成循环依赖；语言规则禁止这种拷贝构造签名。
非 const 的 `T&` 也可能是合法拷贝构造参数，但不能接收 const 对象，通常不符合所需接口。

### 3. 初始化列表与构造函数体内赋值有什么区别？

初始化列表直接构造成员；进入函数体时，成员已经完成初始化。
在函数体里给 string/vector 赋值会经历先默认构造、再赋值。
引用和 const 成员必须在初始化阶段完成必要初始化。
成员实际初始化顺序由类内声明顺序决定，不由初始化列表的书写顺序决定。

### 4. 左值、纯右值、将亡值在本课如何区分？

| 表达式 | 值类别 | 本课理解 |
|---|---|---|
| `a`、`other`、`*this` | 左值 lvalue | 指向有身份的对象，可作为通常的拷贝来源 |
| `MeasurementPacket("IMU", 3, 0.1)` | 纯右值 prvalue | 可用于直接初始化结果对象 |
| `std::move(a)` | 将亡值 xvalue | 仍指向 a，允许被移动操作接收 |

“右值”包括纯右值和将亡值；不能只靠“在等号左边还是右边”判断值类别。
类型与表达式值类别是不同概念：即使 other 的声明类型是 `T&&`，表达式 `other` 仍是左值。
本课固定类型的 `T&&` 是右值引用，不是模板中的转发引用。

### 5. std::move 到底做了什么？

它在 `<utility>` 中，把表达式转换成可绑定右值引用的形式；本身不复制、不移动、不释放资源。
对这里的非 const T 对象 a，可理解为把 a 转成 `T&&` 表达式。
随后由重载选择决定调用哪个函数，函数体决定如何处理资源。
因此只写 `std::move(a);` 并丢弃结果，不会把 a 清空。

### 6. 使用 std::move 一定会移动吗？

不一定。常见情况：

- 没有可用的移动重载，但有 `const T&` 拷贝重载：可能拷贝。
- 来源是 const：通常得到 `const T&&`，不能绑定普通 `T&&` 移动参数，可能拷贝。
- 显式声明 `T(T&&) = delete`：该重载仍可能被选为最佳匹配，随后编译失败，不能假设自动退回拷贝。
- 默认化但因成员限制而被定义为删除的移动构造有特殊规则，会被重载决议忽略；不要和显式删除混为一谈。

参考：[拷贝/移动构造规则](https://eel.is/c++draft/class.copy.ctor)。

### 7. 移动为什么可能比拷贝快？一定是 O(1) 吗？

vector 拷贝通常需要存储空间并复制每个元素；本课 vector 的移动构造可以接管缓冲区，避免逐元素复制。
但移动不保证更快，也不保证统一为 O(1)：小对象可能没有收益，短字符串可能复制内联字符，
某些带分配器的移动需要逐元素处理，移动赋值还要考虑目标原有资源的清理。
对 int 等标量，移动和复制值通常没有成本差异。

### 8. 移动后源对象能做什么？析构为什么不会重复释放？

对本课使用的标准库成员，通常可以依赖“有效但状态未指定”；可析构、可重新赋值，
其他操作仍须满足前置条件，例如读取首元素前要求非空。
正确的移动实现会调整资源管理状态，避免两个对象都把同一资源当成独占资源释放。
自定义类必须自己维护不变量，不能仅靠参数写成 `T&&` 就获得安全性。
`unique_ptr` 转移给另一个对象后来源为空有明确保证，不能把这条保证推广到所有类型。

### 9. 自拷贝赋值与自移动必须写 if 判断吗？

不一定，关键是实现对同一对象作为源和目标时仍正确。
本课 string/vector 的拷贝赋值能处理自赋值，所以 `a = a` 安全。
当前移动赋值显式判断 `this == &other` 并早返回，使 `a = std::move(a)` 保留原值。
一般不能假设所有类型自移动后保留原内容；直接管理资源的实现尤其要避免先释放来源资源再访问它。

### 10. Rule of Three、Five、Zero 分别是什么？

| 规则 | 内容 | 典型使用场景 |
|---|---|---|
| Rule of Three | 需要专门处理析构、拷贝构造、拷贝赋值之一时，通常一起考虑三者 | 直接拥有资源的传统可复制类 |
| Rule of Five | 加上移动构造、移动赋值，一起设计五个操作 | 需要自定义所有权语义的资源封装 |
| Rule of Zero | 不自行声明这五个操作，让资源管理成员与编译器承担工作 | 由 string/vector 等组成的业务数据类 |

这些是设计指导，不是必须实现某个数量的语法规定。
可以禁止复制、允许移动；也可以全部禁止。关键是表达类型允许的操作。
“三法则”不等于“默认构造、虚析构、拷贝构造”。

### 11. 什么情况下编译器会隐式生成移动操作？

对本课普通类，隐式声明移动构造/移动赋值要求没有用户声明的拷贝构造、拷贝赋值、
移动构造、移动赋值和析构函数。相关成员操作也必须可用，否则生成的操作可能被定义为删除。
即使写 `~T() = default;`，也属于用户声明析构函数，会抑制隐式移动。
只写普通带参构造函数不会因此抑制隐式移动。

反过来，声明移动构造或移动赋值会使隐式声明的拷贝操作被定义为删除；
若希望同时支持拷贝，需要按需显式声明。不要机械认为“写了一个，其他四个都自动存在且可用”。

### 12. = default 和 = delete 有什么区别？

`= default` 请求编译器按语言规则生成实现；`= delete` 明确禁止该操作。
默认化不保证函数最终可用，例如含 unique_ptr 的类默认化拷贝仍可能被定义为删除。
默认生成的拷贝/移动按基类和成员逐一处理，不会自动猜测裸指针代表拥有还是观察。

```cpp
// 仅表示接口设计示意，具体实现仍取决于资源类型。
Owner(const Owner&) = delete;
Owner& operator=(const Owner&) = delete;
```

### 13. 默认拷贝一定是浅拷贝吗？

准确说法是“逐成员拷贝”，结果取决于成员类型：

- 拥有资源的裸指针：复制地址，不自动复制所指对象。
- `vector<double>`：复制元素，形成独立测量数组。
- `shared_ptr<T>`：复制共享所有权，不复制 T 对象。
- `unique_ptr<T>`：禁止复制，因此包含它的类通常不可默认拷贝。
- `vector<T*>`：复制一组指针，不会顺带深拷贝指向的所有 T。

因此，浅拷贝/深拷贝应针对具体资源和所有权讨论，而不是仅凭“默认”或“手写”判断。

### 14. 移动构造为什么常标 noexcept？

它向调用方提供“不抛异常”的承诺，便于容器在迁移元素时使用移动并保持异常保证。
尤其要区分：扩容主要在新存储中构造旧元素，关注移动构造；已有对象之间替换内容才是移动赋值。
`noexcept` 不会让本来可能抛异常的代码变得安全，异常逃出会终止程序。

### 15. 拷贝赋值是否天然具有强异常保证？

不是。本课依次执行 `sensor_name_ = other.sensor_name_` 与 `values_ = other.values_`。
如果第一步成功、第二步分配失败，目标可能已部分更新，不能声称整体保持赋值前原样。
资源仍由标准库成员管理，但“没有泄漏”和“失败时对象完全不变”是不同保证。
需要强异常保证时，可考虑先构造完整副本，再通过满足不抛异常条件的 swap 提交；
是否采用这种写法应结合类的不变量与成本决定。

### 16. C++17 的保证消除与 NRVO 有什么区别？

本例 `T make() { return T(...); }` 直接返回同类型纯右值，结果直接构造，
可以不依赖可用的拷贝/移动构造函数，但析构函数等仍须满足相应可访问性要求。
`T make() { T local(...); return local; }` 是具名局部对象返回，NRVO 是可选消除，
必须考虑未消除时初始化结果是否合法，不能靠编译器“可能优化”挽救不可用的操作。

### 17. 禁用拷贝消除为什么还有没有移动日志的情况？

GCC/Clang 的 `-fno-elide-constructors` 用于禁用可选消除，不能取消本例 C++17 要求的直接构造。
所以对照版 direct return 仍没有 move，named return 出现一次 move；这正是两类规则的区别。

### 18. emplace_back 一定比 push_back 好吗？

不一定。传构造参数时，emplace_back 可以在容器位置直接构造元素，省去外部临时包。
已有对象时，两者仍按来源的值类别进行拷贝或移动；容量不够时两者都可能触发旧元素迁移。
选择应以表达意图清楚为先，性能差异通过实际场景测量。

### 19. this 与 data 地址说明了什么，不能说明什么？

this 表示包对象的位置；data 表示包内 vector 的元素存储。
移动后包的 this 可以不同，而 data 相同，说明当前实现接管了同一数组。
对象销毁后，后续对象可能复用相同地址，所以不同时间日志里地址相同，不代表是同一个活对象。
地址观察不能替代生命周期规则，也不能直接证明性能收益。

### 20. 普通类必须有默认构造或虚析构吗？

不必。需要无参数创建时才设计默认构造；普通带参构造已满足需求时无需补齐形式。
需要通过基类指针删除派生对象的常规多态接口，应提供适当的虚析构；普通数据包不必加 virtual。
析构函数体结束后，成员仍会自动按声明的逆序析构，本课不需要再手工释放 string/vector 的内存。
